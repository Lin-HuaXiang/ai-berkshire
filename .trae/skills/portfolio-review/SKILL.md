# 组合管理与优化：Portfolio Review

对 $ARGUMENTS 指定的投资组合进行全面体检与优化分析。本 Skill 采用单 Agent 顺序执行五步流程，从持仓解析到压力测试，最终输出调仓建议并保存组合报告。

## 输出可读性规则：缩写中文括注

- 报告、表格、标题和结论里出现英文或财务缩写时，必须在旁边用小括号写中文含义，尤其是首次出现和表格标题。
- 重点包括但不限于：FY（财年）、FCF（自由现金流）、OCF（经营现金流）、PE（市盈率）、PB（市净率）、PS（市销率）、EV（企业价值）、EPS（每股收益）、ROE（净资产收益率）、ROIC（投入资本回报率）、ROI（投资回报率）、CAGR（复合年增长率）、CapEx（资本开支）、SBC（股权激励费用）、GAAP（美国通用会计准则）、Non-GAAP（非美国通用会计准则）、EBITDA（息税折旧摊销前利润）、EBIT（息税前利润）、GMV（商品交易总额）、AUM（资产管理规模）、LTV（用户生命周期价值）、CAC（获客成本）。
- 示例：FY2025（2025 财年）、FCF（自由现金流）、PE（市盈率）、ROE（净资产收益率）。
- 同一缩写在同一段落内可不重复解释，但跨章节、表格表头、图表标题再次出现时仍要补中文括注，保证单独截取也能读懂。

## 核心原则

- **每一块钱都有机会成本** —— 持有A意味着放弃B，永远问"这笔钱现在最好的去处是哪？"
- **集中不是风险，无知才是** —— 深度了解的高集中度远胜分散的平庸
- **现金是一种仓位** —— 现金的隐含回报率是无风险利率 + 机会选择权价值

## 执行流程

### 第一步：解析持仓

要求用户提供当前持仓情况（或从 `reports/portfolio-latest.md` 读取）。将持仓标准化为以下表格：

| 序号 | 标的 | 代码 | 持仓量 | 成本价 | 现价 | 市值 | 占比 | 盈亏% | 持有周期 |
|------|------|------|--------|--------|------|------|------|-------|----------|
| 1 | | | | | | | | | |

计算：
- 总市值、总成本、总盈亏
- 现金占比（如用户提供现金数据）
- 各标的仓位百分比

### 第二步：获取最新数据

对每个持仓标的，通过以下方式获取最新数据：

1. **WebSearch**：搜索最新股价、估值（PE/PB/PS）、最新财报变化、重大事件（近3个月）
   - 搜索关键词："{公司名} stock price {日期}"、"{公司名} latest earnings"、"{公司名} news"
2. **估值验算**（使用 Python 工具）：
   ```bash
   python3 tools/financial_rigor.py verify-valuation --price {现价} --eps {最新EPS} --bvps {每股净资产}
   ```
3. **市值验算**：
   ```bash
   python3 tools/financial_rigor.py verify-market-cap --price {现价} --shares {总股本亿} --reported {报告市值亿} --currency {币种}
   ```

汇总为"最新数据快照"表，标注数据日期和来源。

### 第三步：单仓位体检

对每个持仓进行三项检查：

#### 3.1 估值体检

- 当前 PE（市盈率）vs 历史PE区间（3-5年）
- 当前 PB（市净率）vs 历史PB区间
- 当前 PS（市销率）vs 行业平均水平
- 当前股息率 vs 历史股息率
- 估值分位数判断：偏高/合理/偏低

#### 3.2 买入逻辑变化检查

- 原始投资论文中的核心假设是否仍然成立？
- 管理层是否有重大变化？
- 竞争格局是否恶化？
- 行业趋势是否逆转？

#### 3.3 三个灵魂问题

对每个持仓回答：

| 问题 | 回答（是/否/不确定） | 理由 |
|------|---------------------|------|
| 如果今天没有持仓，我会按现价买入吗？ | | |
| 我确信5年后这家公司仍然值得持有吗？ | | |
| 我的投资论文仍然完整吗？（关键假设是否破裂？） | | |

三个问题全"Yes" → 持仓健康，可以继续持有甚至加仓
两个"No" → 需要警惕，考虑减仓或清仓
任何问题"不确定" → 需要深入研究

### 第四步：组合层面分析

#### 4.1 集中度分析

计算并展示：
- 第一大持仓占比（红线：>40% 标红警告，>50% 要求用户确认）
- 前三大持仓合计占比（理想区间：50-80%）
- 前五大持仓合计占比
- 赫芬达尔指数（HHI）

> 参考标准：巴菲特前5大持仓通常占70-80%，但每个他都非常了解。集中本身不是问题，不了解才是。

#### 4.2 相关性检查

| 维度 | 暴露情况 | 风险等级 |
|------|---------|----------|
| 同行业集中度（如多个科技股） | 列出同行业标的及合计占比 | 低/中/高 |
| 同国家/市场集中度（如全是A股） | 列出市场分布及占比 | 低/中/高 |
| 同主题暴露（如全是AI相关） | 列出主题分布及占比 | 低/中/高 |
| 同产业链位置（如全是上游） | 列出产业链位置分布 | 低/中/高 |
| 货币暴露（汇率风险） | 列出各币种占比 | 低/中/高 |

> 问题：如果某个共同风险同时打击多个持仓，组合损失会有多大？

#### 4.3 机会成本分析

对每个持仓，按以下步骤进行机会成本排序：

1. **预期年化回报估算**（使用三情景模型）：
   ```bash
   python3 tools/financial_rigor.py three-scenario --price {现价} --eps {EPS} --shares {股本亿} --growth {乐观} {中性} {悲观} --pe {乐观PE} {中性PE} {悲观PE} --years 3 --currency {币种}
   ```
2. **回报排序**：将各标的预期年化回报从高到低排列
3. **最差情景检查**：每个标的在悲观情景下的回报率。如果最差情景仍 > 4%（现金收益率），说明安全边际足够

输出"预期回报排序表"：

| 标的 | 乐观CAGR | 中性CAGR | 悲观CAGR | 当前仓位 | 建议方向 |
|------|---------|---------|---------|---------|---------|
| | | | | | |

#### 4.4 压力测试

对组合进行四种极端情景的冲击模拟：

| 情景 | 假设条件 | 对组合影响评估 |
|------|---------|--------------|
| 全球衰退 | 股市整体下跌30-50%，高杠杆/周期性公司跌更多 | 逐个标的评估跌幅 + 组合总跌幅估算 |
| 中美冲突升级 | 贸易脱钩、科技制裁、供应链断裂 | 逐个标的评估受影响程度 |
| 利率飙升 | 10年期美债利率升至6%+，成长股重估 | 逐个标的重新估值，计算潜在跌幅 |
| 科技泡沫破裂 | 科技股跌幅60%+，回归基本面估值 | 逐个标的按"回到历史均值PE"计算跌幅 |

输出"压力测试汇总表"：每个标的在四种情景下的预估跌幅+组合总跌幅。

### 第五步：优化建议

综合以上分析，输出调仓建议表：

| 标的 | 当前仓位 | 建议仓位 | 操作 | 理由 |
|------|---------|---------|------|------|
| | | | 加仓/减仓/清仓/新建仓/不动 | |

#### 现金管理

- 当前现金占比：X%
- 建议现金占比：Y%
- 理由：基于当前市场估值水平+组合安全边际+潜在机会储备

> 巴菲特原则：在别人贪婪时恐惧（保持现金），在别人恐惧时贪婪（部署现金）。

### 第六步：输出组合报告

将完整分析结果写入 `reports/portfolio-latest.md`（根目录），包含：

---

#### 报告结构

1. **组合概览**：总市值、总成本、总盈亏、持仓数量、现金占比
2. **持仓明细表**：标准化表格
3. **单仓位体检**：每标的估值+逻辑变化+三灵魂问题
4. **集中度分析**：图表+风险提示
5. **相关性检查**：行业/国家/主题/货币暴露矩阵
6. **机会成本分析**：预期回报排序+三情景结果
7. **压力测试**：四情景冲击模拟
8. **调仓建议表**：具体操作+现金管理建议

#### 结论（必须明确）

- **组合健康度评级**：健康 / 需关注 / 需调整 / 需重整
- **最该做的一件事**：一句话明确指出当前优先级最高的操作
- **最大风险**：组合面临的最大单一风险是什么
- **下一步行动清单**：3-5条具体可执行的操作

## 注意事项

1. 所有估值计算必须使用 `tools/financial_rigor.py` 工具验算，禁止心算
2. 市值必须手算校验：股价 x 总股本，与报告市值对比
3. 货币单位要明确（港币/人民币/美元），防止混淆
4. 估值分位数结论必须标注数据来源和时间范围
5. 压力测试的假设必须明确标注为"假设"或"模拟"，而非预测
6. 如果用户未提供完整的持仓信息，先输出"信息缺口清单"，请用户补充后再继续
