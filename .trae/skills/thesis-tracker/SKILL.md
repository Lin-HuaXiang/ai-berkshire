# 投资论文追踪：买入后的纪律系统

对 $ARGUMENTS 指定的持仓标的建立或追踪投资论文。本 Skill 采用单 Agent 执行，分两种模式：模式A（新建论文）和模式B（追踪检查）。

## 输出可读性规则：缩写中文括注

- 报告、表格、标题和结论里出现英文或财务缩写时，必须在旁边用小括号写中文含义，尤其是首次出现和表格标题。
- 重点包括但不限于：FY（财年）、FCF（自由现金流）、OCF（经营现金流）、PE（市盈率）、PB（市净率）、PS（市销率）、EV（企业价值）、EPS（每股收益）、ROE（净资产收益率）、ROIC（投入资本回报率）、ROI（投资回报率）、CAGR（复合年增长率）、CapEx（资本开支）、SBC（股权激励费用）、GAAP（美国通用会计准则）、Non-GAAP（非美国通用会计准则）、EBITDA（息税折旧摊销前利润）、EBIT（息税前利润）、GMV（商品交易总额）、AUM（资产管理规模）、LTV（用户生命周期价值）、CAC（获客成本）。
- 示例：FY2025（2025 财年）、FCF（自由现金流）、PE（市盈率）、ROE（净资产收益率）。
- 同一缩写在同一段落内可不重复解释，但跨章节、表格表头、图表标题再次出现时仍要补中文括注，保证单独截取也能读懂。

## 核心原则

- **买入前写好卖出条件** —— 没有退出计划的投资不是投资，是投机
- **论文要具体到可验证** —— "公司会继续增长"不叫论文，"未来3年营收CAGR>15%因为X"才是
- **红线触发就行动** —— 预设的红线就是你的纪律，不要等到亏损50%才想起来
- **论文破裂不等于股价下跌** —— 有时候论文完好但股价跌了（这是机会），有时候股价涨了但论文破了（这是陷阱）

## 模式A：建立投资论文

当用户持有或计划买入某个标的时，先建立投资论文作为后续追踪的基线。

### A1：核心论文（5句话，200字以内）

用5句话写清楚你为什么买这家公司。**写不完整 = 论文有问题**。

格式：
1. **生意是什么**：一句话描述核心生意和赚钱方式
2. **为什么现在买**：时机逻辑（估值合理？周期低点？催化剂？）
3. **竞争优势**：护城河在哪，为什么别人抢不走
4. **增长驱动力**：未来3-5年增长来自哪里（量/价/新业务？）
5. **预期退出条件**：什么情况下会卖？（价格达到？论文破裂？找到更好的？）

### A2：核心假设清单（3-7个可验证假设）

| 序号 | 核心假设 | 验证方式 | 验证频率 | 当前状态 |
|------|---------|---------|---------|---------|
| 1 | 例：未来3年营收CAGR≥15% | 季报营收数据 | 每季度 | 成立 |
| 2 | 例：毛利率维持60%以上 | 季报毛利率 | 每季度 | 待验证 |
| ... | | | | |

> 假设要求：可验证、有时间框架、有具体数值。不能用"持续增长"这种模糊表述。

### A3：红线清单

预设卖出/重新评估的触发条件，分三级：

**致命级（触发 = 必须立即卖出，不需要犹豫）**：
- 例：核心管理层大面积离职或CEO辞职
- 例：核心产品/技术被颠覆性替代
- 例：财务造假或重大法律风险

**严重级（触发 = 必须重新评估，大概率减仓/清仓）**：
- 例：连续两个季度营收增速<5%（远低于核心假设的15%）
- 例：毛利率跌破50%（核心假设的60%被打破）
- 例：关键客户/市场流失>20%

**警告级（触发 = 必须写一份追踪报告，密切观察）**：
- 例：核心对手推出同类产品且定价低30%
- 例：行业监管出现重大不利变化趋势
- 例：管理层开始大量减持

### A4：估值锚点

使用 Python 工具进行三情景估值：

```bash
python3 tools/financial_rigor.py three-scenario --price {买入价} --eps {EPS} --shares {股本亿} --growth {乐观} {中性} {悲观} --pe {乐观PE} {中性PE} {悲观PE} --years 3 --currency {币种}
```

输出"估值锚点表"：

| 情景 | 假设 | 3年后EPS | 目标PE | 目标价 | 预期CAGR | 概率权重 |
|------|------|----------|--------|--------|----------|---------|
| 乐观 | | | | | | 20% |
| 中性 | | | | | | 60% |
| 悲观 | | | | | | 20% |

**概率加权预期年化回报**：X%（如果 <8%，请重新考虑这笔投资）

### A5：保存论文

将论文写入 `reports/{TICKER}/{TICKER}-thesis.md`。包含：

1. 核心论文（5句话）
2. 核心假设清单
3. 红线清单
4. 估值锚点
5. 买入时的关键数据快照（股价、PE、PB、市值、营收、净利润）
6. 建立日期

## 模式B：追踪检查

当用户需要对已有论文的持仓进行定期检查时使用。

### B1：读取现有论文

从 `reports/{TICKER}/{TICKER}-thesis.md` 读取论文。如果文件不存在，提示用户先使用模式A建立论文。

### B2：收集最新数据

使用 WebSearch 收集：
- 最新股价、市值、估值指标
- 最新季度财报数据（营收、净利润、毛利率、FCF等）
- 重大事件（管理层变动、新产品/竞争对手动态、监管变化）
- 卖方评级变化、机构持仓变化

### B3：逐条检查核心假设

| 假设 | 原状态 | 最新数据 | 判定 | 证据 |
|------|--------|---------|------|------|
| 假设1 | 成立 | | 🟢/🟡/🔴/⚫ | |
| 假设2 | 成立 | | 🟢/🟡/🔴/⚫ | |

判定标准：
- 🟢 **成立**：数据持续支持假设，无需调整
- 🟡 **边际弱化**：数据有走弱迹象但尚在可接受范围，需要密切观察
- 🔴 **受损**：数据明显偏离假设，需要重新评估论文
- ⚫ **破裂**：假设被证伪，论文的核心逻辑动摇

### B4：红线检查

逐条检查预设的红线清单：

| 红线 | 级别 | 触发状态 | 证据 | 建议动作 |
|------|------|---------|------|---------|
| | 致命/严重/警告 | 已触发/未触发/接近触发 | | |

如果任何等级的红线被触发，立即执行预设动作（卖出/重新评估/写报告）。

### B5：估值更新

```bash
python3 tools/financial_rigor.py three-scenario --price {最新价} --eps {最新EPS} --shares {股本亿} --growth {乐观} {中性} {悲观} --pe {乐观PE} {中性PE} {悲观PE} --years 3 --currency {币种}
```

对比买入时的估值锚点，判断当前估值位置：

| | 买入时 | 当前 | 变化 |
|------|--------|------|------|
| 股价 | | | |
| PE（市盈率） | | | |
| 中性情景目标价 | | | |
| 安全边际（当前价/中性目标价-1） | | | |

### B6：输出追踪报告

将追踪结果写入 `reports/{TICKER}/{TICKER}-thesis.md` 的"追踪记录"section（追加在论文文件末尾）。

追踪报告结构：

1. **追踪日期** + **距上次追踪的时间间隔**
2. **论文健康度评分**：
   - 健康度 = 10 - (⚫数量 x3) - (🔴数量 x2) - (🟡数量 x1) - (红线触发数量 x5)
   - 最低0分，最高10分
3. **健康度解读**：
   - 9-10分：论文完整，可以考虑加仓
   - 7-8分：论文基本完整，持有
   - 5-6分：论文出现裂痕，提高警惕
   - 3-4分：论文严重受损，考虑减仓
   - 1-2分：论文破裂，强烈建议卖出
4. **假设检查详情**（逐条+证据+判定）
5. **红线检查详情**（逐条+触发状态+行动）
6. **估值更新对比**（买入 vs 当前）
7. **关键变化摘要**：自上次追踪以来的3-5项最重要变化
8. **行动建议**：加仓/持有/减仓/清仓 + 具体价格区间

### B7：追加追踪记录

每次追踪都在论文文件的 `## 追踪记录` section 下追加一个新的记录块：

```markdown
### {YYYY-MM-DD} 追踪

- **健康度评分**：X/10
- **健康度等级**：{等级}
- **关键变化**：...
- **行动建议**：...
- **下次追踪日期**：{建议日期}
```

## 注意事项

1. 论文是"活的文档"，每次追踪后更新假设状态但不删除历史记录
2. 如果论文已破裂（健康度1-2分），在文件中明确标注 "⚠️ 论文已破裂 — 建议卖出"
3. 不要因为股价下跌就修改论文 —— 区分"论文破裂"和"股价下跌"
4. 不要因为股价上涨就忽略论文裂痕 —— 股价泡沫中的论文破裂最危险
5. 论文文件放在 `reports/{TICKER}/` 目录下，TICKER使用英文/拼音，禁止中文
6. 所有估值计算使用 Python 工具验算
