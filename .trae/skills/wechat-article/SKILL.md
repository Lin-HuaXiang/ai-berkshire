# 微信公众号文章：三阶段协作写作

基于 $ARGUMENTS 指定的主题，按照作者-编辑-读者三阶段流程，产出可直接发布的微信公众号深度文章。

## 输出可读性规则：缩写中文括注

- 报告、表格、标题和结论里出现英文或财务缩写时，必须在旁边用小括号写中文含义，尤其是首次出现和表格标题。
- 重点包括但不限于：FY（财年）、FCF（自由现金流）、OCF（经营现金流）、PE（市盈率）、PB（市净率）、PS（市销率）、EV（企业价值）、EPS（每股收益）、ROE（净资产收益率）、ROIC（投入资本回报率）、ROI（投资回报率）、CAGR（复合年增长率）、CapEx（资本开支）、SBC（股权激励费用）、GAAP（美国通用会计准则）、Non-GAAP（非美国通用会计准则）、EBITDA（息税折旧摊销前利润）、EBIT（息税前利润）、GMV（商品交易总额）、AUM（资产管理规模）、LTV（用户生命周期价值）、CAC（获客成本）。
- 示例：FY2025（2025 财年）、FCF（自由现金流）、PE（市盈率）、ROE（净资产收益率）。
- 同一缩写在同一段落内可不重复解释，但跨章节、表格表头、图表标题再次出现时仍要补中文括注，保证单独截取也能读懂。

## 写作红线（9条铁律，不可违背）

1. **不虚构数据**。所有数据必须有来源。估算值必须标注"估算"。
2. **不用AI腔调**。禁用"值得注意的是"、"综上所述"、"赋能"、"抓手"、"底层逻辑"、"闭环"。像写给你最聪明的那个朋友看。
3. **不过度承诺**。不写"这篇文章改变你的人生"、"看完你就懂了"。
4. **公式配大白话**。每个数学/金融公式后面，必须用一句所有人都看得懂的大白话解释。
5. **公式使用LaTeX**。所有数学公式使用 `$$...$$` 格式。
6. **配图必须实际插入**。用 `![描述](路径)` 实际引用图片，不能只写"此处应有图"。配图从assets/或截图提取，文件大小 ≥ 500KB。
7. **类比必须一以贯之**。选定一个类比后全文使用，不要开头用"航海"、中间换"下棋"。
8. **结尾必须有传播力**。要么让读者忍不住转发（金句/洞见），要么给明确可执行的下一步。
9. **不要使用**"首先、其次、再者、此外、另外、最后、总体而言、基于、上述、值得注意的是、综上所述"等AI高频词汇。

## Stage 1：研究与素材收集（作者角色）

### 1.1 确认文章定位

从用户输入提取或主动询问：

| 维度 | 选项参考 | 说明 |
|------|---------|------|
| 目标读者 | 投资专业读者 / 泛财经读者 / 普通大众 | 决定专业度和表达方式 |
| 文章深度 | 入门科普（3000字） / 中深度（5000字） / 深度报告（8000字+） | 决定信息密度和研究工作量 |
| 文章长度 | 3000 / 5000 / 8000+ 字 | 对应阅读时间约8/15/25分钟 |
| 风格定调 | 纪实报道 / 深度分析 / 观点评论 / 叙事故事 | 决定开头方式和结构 |

如果用户没有明确，默认为：泛财经读者 / 中深度（5000字） / 深度分析风格。

### 1.2 三维并行研究

同时从三个方向进行素材收集：

#### 方向1：核心内容研究

使用 WebSearch 搜索文章主题的核心信息和数据：
- 搜索中英文关键词
- 覆盖：事实数据、最新动态、关键数字、专家观点
- 至少交叉验证3个关键数据点

#### 方向2：行业背景与历史脉络

使用 WebSearch 和 WebFetch：
- 搜索行业历史发展脉络和时间线
- 搜索关键转折点和标志性事件
- 为文章提供纵深感和"讲故事"的素材

#### 方向3：竞品/对比研究

使用 WebSearch：
- 搜索同类主题已有的爆款文章（公众号、知乎、雪球）
- 分析它们的切入角度、叙事结构、数据使用
- 找出你的差异化角度（别人没说透/没说的那个点）

### 1.3 整理素材框架

将收集的素材组织为：

```
文章主题：XXX
核心角度（差异化）：XXX
文章大纲：
  1. 开头钩子（1-2段）
  2. 背景与问题（2-3段）
  3. 核心分析（主体，4-6段）
  4. 关键证据（2-3段）
  5. 展望与思考（1-2段）
  6. 结尾金句/行动建议（1段）
关键数据清单：[数据1（来源A+来源B交叉验证）, ...]
引用素材：[原文引用1, ...]
```

## Stage 2：写初稿（作者角色）

### 写作原则

- **纯中文**：避免中英文混杂。专业术语首次出现时用中文全称+英文缩写括注
- **写给聪明朋友**：像在跟一个聪明的朋友聊天，不居高临下，不说废话
- **每段不超过4行**：手机屏幕上一屏能看到完整一段。段落之间留空行
- **一句话段落允许**：重要的结论单独成段，制造节奏感
- **用短句**：能用句号不用逗号。复杂的逻辑拆成多个短句

### 结构要求

#### 开头：强钩子（前3段）

必须在前3段内让读者产生"必须读完"的冲动。技巧：
- 一个有力的数据/事实
- 一个矛盾/反直觉的现象
- 一个问题/悬念
- 一个小故事/场景

反面教材（禁止的写法）：
- "随着...的发展..."
- "近年来...越来越..."
- "在当今时代..."

#### 背景：设置问题

告诉读者"为什么现在要关注这个"、"这个问题为什么重要"。快速建立背景，1-2段即可。

#### 核心内容：深度+大白话

这是文章的主体，占全文50-60%。

- 数据说话：用数据支撑每个判断
- 大白话解释：每个复杂概念后面紧跟一句所有人都看得懂的解释
- 案例/故事穿插：用具体的企业案例或人物故事让抽象概念具体化
- 图表穿插：关键数据用表格呈现，趋势用文字描述

表格示例格式：

| 维度 | A公司 | B公司 | C公司 |
|------|-------|-------|-------|
| 营收（亿元） | 100 | 80 | 60 |
| 毛利率 | 45% | 38% | 52% |

#### 实证部分：关键证据

用2-3个最有说服力的证据支持核心论点。证据之间要有互补关系（不同角度），不要重复。

#### 展望：有依据的推测

基于前面的分析，给出对未来的思考。但要标明"推测"、"估计"、"可能"。

#### 结尾：有传播力

让读者想转发、想行动。技巧：
- 一句凝练的金句
- 一个让人记住的类比
- 一个明确的"你可以做什么"的行动建议
- 一个让人继续思考的问题

反面教材：禁止"让我们一起期待"、"未来可期"等空洞结尾

### 配图规则

- 必须使用 `![描述](路径)` 实际引用图片
- 优先从 `assets/` 目录选取已有图片
- 如果从PDF/网页提取图片，通过截图工具保存到 `assets/` 目录
- 图片文件大小 ≥ 500KB（太小说明质量不够）
- 每1500-2000字至少配一张图
- 图表类配图优先于装饰类配图

### 公式规则

- 所有数学公式使用 LaTeX 格式：`$$...$$`
- 每个公式后面必须有一句大白话解释
- 示例：

> $$ \text{FCF} = \text{经营现金流} - \text{资本开支} $$
>
> 翻译成人话：公司一年真正赚到的现金 = 经营挣来的钱 - 维持经营必须花掉的钱

## Stage 3：编辑审阅 + 读者审阅

### 3.1 编辑审阅（7项标准）

以编辑（而非作者）的身份对初稿进行逐项检查：

| 检查项 | 标准 | 常见问题 |
|--------|------|---------|
| 标题 | 有人会点进去吗？3秒内能判断文章价值吗？ | 太笼统、太长、没有信息差 |
| 开头 | 前3段能抓住人吗？ | 铺垫太多、没有钩子、AI腔 |
| 结构逻辑 | 论证链条完整吗？有跳跃吗？ | 结论前置但论证跟不上、漏了关键论据 |
| 深度与可读性 | 专业但不枯燥？读者能跟上吗？ | 堆数据没有解释、大白话不够 |
| 节奏 | 有没有喘气的地方？一直高密度？ | 全是数据喘不过气、故事之后没有沉淀 |
| 配图 | 图真的有用吗？位置对吗？ | 纯装饰图、图中信息与文字重复 |
| 结尾 | 读者看完会做什么？ | 虎头蛇尾、说教、空喊口号 |

输出"编辑修订版"：在初稿基础上直接修改，用 `[编辑注：...]` 标注有疑问的地方。

### 3.2 读者审阅（8个问题）

以目标读者的身份（切换到读者的知识水平、阅读场景、注意力状态），回答以下8个问题：

| 编号 | 问题 | 回答格式 |
|------|------|---------|
| 1 | 你愿意读完前3段吗？不愿意的话从哪句话开始想划走？ | 诚实回答，指到具体句子 |
| 2 | 有没有哪一段你读了两遍还没懂？ | 如有，指出是哪一段+为什么 |
| 3 | 文中的公式你看了吗？看了的话看懂了吗？ | 诚实回答 |
| 4 | 文中的类比让你更理解了还是更困惑了？ | 具体评价 |
| 5 | 你在哪一段开始想"划一下看结尾"？ | 指出位置 |
| 6 | 读完后你能用一句话说出这篇文章的核心观点吗？ | 用你自己的话复述 |
| 7 | 你会转发这篇文章吗？会的话转发语写什么？ | 写一句转发语 |
| 8 | 你觉得哪里没说透？想问但文章没回答的问题是什么？ | 列1-3个问题 |

### 3.3 定稿原则

处理编辑和读者的反馈，按以下优先级：

| 优先级 | 情况 | 处理方式 |
|--------|------|---------|
| P0（必改） | 编辑和读者都指出同一个问题 | 必须修改 |
| P1（大概率改） | 仅编辑指出 | 大概率采纳，除非你有充分理由 |
| P2（视情况） | 仅读者指出 | 评估是否影响阅读体验，影响则改 |
| 矛盾处理 | 编辑和读者意见相悖 | 偏向读者感受（因为读者是最终消费者） |

定稿检查清单：
- [ ] 9条写作红线全部通过
- [ ] 所有数据有来源
- [ ] 所有公式有LaTeX+大白话解释
- [ ] 配图实际插入（非占位符）
- [ ] 缩写首次出现有中文括注
- [ ] 没有AI高频词汇
- [ ] 结尾有传播力

根据文章类型选择保存路径：

| 文章类型 | 保存路径 | 示例 |
|---------|---------|------|
| 技术/产业研究 | `reports/AI-Industry/` | `reports/AI-Industry/AI-suanli-20260708.md` |

文件名格式：`{主题英文}-wechat-{YYYYMMDD}.md` 或 `{主题英文}-{YYYYMMDD}.md`

在文章末尾追加参考链接/延伸阅读（如有）。

## 注意事项

1. 三阶段是顺序执行的（先研究、再写作、后审阅），不要在写作中途跳到编辑模式
2. Stage 2 写初稿时不要边写边改 —— 先把内容写出来，Stage 3 再打磨
3. 编辑审阅和读者审阅是两轮独立的检查，分别输出
4. 如果文章涉及投资建议，必须加上免责声明
5. 所有文件路径中的目录名和文件名使用英文/拼音，禁止中文
6. 公众号文章每段不超过4行的规则是为了手机阅读的节奏感，PC端编辑时容易忽视
